# 节奏：语速、气口、可见变化

短视频观众在气口处划走。语速是**实测的字/秒**（`norm()` 后的可发音字符 ÷ 剪辑后秒数），不是 provider 的参数；参数由 `tts.py calibrate` 按声线实测，再由用户在开头确认点听。

## 数字

| 项 | 爆款（viral） | 宣发（launch） | 依据 |
|---|---|---|---|
| 目标语速 `pacing.targetCps` | **8.0 ± 0.8** | **7.4 ± 0.5** | 已确认成片实测 7.7–8.9；曼波声线 Fish speed 1.5 ≈ 7.9、1.65 ≈ 8.2 |
| 句内最长停顿 | ≤ 0.24 s（`voiceEdit.maxInternalPauseSeconds` 0.30 → 压到 0.18） | ≤ 0.35 s | 实测成片 0.16–0.34 |
| 段间气口 `gapPolicy` | `。` 0.30 · `？！` 0.40 · `…` 0.50 · `，` 0.20；`turn` 0.50 · `chapter` 0.60 · `ending` 0.60 | 各 +0.15 s；录屏证据段可到 2.5 s | 手调间隔表 0.25–0.6 s |
| 气口硬上限 `maxVoiceGapSeconds` | **0.8 s**，超过必须登记 `film.voices[].gapIntent.reason` | 2.5 s，且该区间必须有画面在动 | 唯一合法的长空档是"证据自己在放" |
| 首段前导 `leadSeconds` | 0.3 s | 0.4 s | 首帧就是封面视觉，声音略后到 |
| 结尾静音 `maxTrailingSilenceSeconds` | 2.0 s | 2.5 s | 结尾卡停留给收藏，不给发呆 |
| 可见变化间隔 `visualChangeMaxSeconds` | **1.5 s** | 2.5 s | "每 1–2 秒必须有一个可见变化"；`render.py` 渲后与 `qa.py` 用同一把尺：96×54 灰度、10 fps，相邻帧均差 > 1.5 或自上次变化起累计漂移 > 1.5 记一次变化（慢推、计数器、光标扫过都算），字幕带不计；录屏等观众跟着看的镜头用 `film.shots[].hold: "原因"` 登记，不计入 |
| 响度 | −14 LUFS / TP −1.5 dBTP（手机播放要更响可到 −11） | 同 | 已有成片 −15/−3.6 偏轻 |
| BGM 重击对位 | ≤ 2 帧 | 无硬要求 | 三条成片实测 drop / 词首 / 硬切同帧 |

`tts.py calibrate <project> --sweep 1.3,1.45,1.6 --target-cps 8.0` 会合成同一句、剪气口、报告每档的实测字/秒并写入 brief。清晰度比数字重要：8.2 字/秒时英文与数字要靠 `overrides` 写成读法（GPT-6 → GPT 六）。

## 气口三步

1. **压**：`voice_edit.py`（`tts.py` 自动调用）裁首尾、把句内 >0.30 s 的停顿对称压到 0.18 s，时间戳跟着重映射；缓存永远不会交付未剪的音频（synth 与 edit 指纹同时匹配才复用）。
2. **排**：`project.py plan-voices` 按标点／段落类型给段间间隔，`voices[].at = {after, offset}` 用实测音频长度接续。
3. **查**：`validate.py` 报告超限的气口、尾部静音与偏离目标的语速；两包默认 `pacing.enforce: true`，**只把这三类升级为错误**（禁词、字幕宽度、素材、产品证据仍是警告），且只在非草稿阶段（opening / preview / final）阻断，技术草稿照常出。`render.py` 每次渲染后在真实像素上量静止段：草稿 / 开头阶段警告，preview / final 在 enforce 下直接拒绝；`qa.py` 另报 16:9 的内容摆放（placement）。

## 没有死气口

任何 > 0.5 s 的无声区间只允许三种：
- **有意停顿**：反转前、顿悟前、CTA 前。登记 `gapIntent.reason`，且画面**必须在动**（推近、计数器滚动、印章落下、进度条呼吸）。
- **证据播放**：录屏／演示原声在说话。
- 否则是缺陷。处理顺序：先压静音 → 再补一句口播 → 最后才改镜头时长。**不要**整体加速长版来提速。

## 声音之外的节奏

- 前 3 秒：主体 + 断言 + 证据同屏；静音也能懂（60% 的人静音刷）。
- 每 25 秒一个新事实或判断；同一个数字只出现一次。
- 转折（turn）落在 35–75%；结尾卡停留 ≥ 2.5 s 给截图。
- 字幕一次一个意群，≤ 16 字（加权 ≤ 14：中文 1、英文数字 0.6）。

## 宿主 TTS 的语速回路（qwen-audio-3.0 等）

两条实测宿主成片（2026-09-11，59.8 s 与 64.5 s）：语速 **4.0 / 4.2 字/秒**，是目标的一半；同样 264 字按 8 字/秒只要 35 秒。整体加速救不回来：`atempo` 1.25× 时 whisper 匹配 0.95、只到 5.0 字/秒，1.5× 掉到 0.905、才 6.0 字/秒。所以：

1. `tts.py plan`：每段给 `instruction`（含"按每秒约 N 个汉字朗读，这是硬性要求"）、内联标签、`expectedSeconds`（字数 ÷ 目标语速的区间）；工具若有数字语速参数先设 1.3–1.5。
2. 生成 → `tts.py import`：自动剪气口并打印 `pace ✓ / ⚠`。⚠ 偏慢就改 instruction 更快或调高语速参数**重新生成**，不要接受。
3. 最后手段 `tts.py import --tempo 1.2`（上限 1.3，时间戳自动缩放，index 记录 tempo）：音质降级，只能补 30%，不能替代第 2 步。
4. 全部 ✓ 后 `project.py plan-voices` 排段间气口（实测成片段间静音 0.5–1.3 s，是没跑这一步）。
