# 成片验收：机器证据与实际视听分开

执行接口以 [layout-and-qa.md](layout-and-qa.md) 为准；本文件不再保留旧版“必需素材只警告”“生成接触表就算看过”的规则。

## 创意判断

影片首先要让人愿意看，而不是先堆特效。开头尽早展示结果、反差或可验证的问题；中段让每次切换带来新的理解；结尾交代结论、边界或可执行动作。真实界面、生成画面和概念示意应明确区分。不要把每个镜头都做成同样的白卡片。

三个协作节点是方案卡、完整脚本、真实前十秒动态样片。后两者沿用原脚本/开头批准机制，必须来自实际用户回复，不能由 Agent 填“自动批准”。继承已经有效的批准，不重复询问。`review.py carry-opening` 只适用于满足原解码比对规则的重渲；它不是新内容的批准。

## 硬检查与观察提示

| 层 | 实际检查 | 限制 |
|---|---|---|
| 素材 | `materials.py check` / `validate.py`：必需材料、实际可解码文件、来源/使用依据、当前审阅摘要、对应镜头声明 | 无法证明审核者真正看过；语义、权利解释仍需人判断 |
| 几何 | `SafeText` 与 `LayoutGuard`：实际字体布局、最小字号、容器溢出、已标注元素的区域/重叠 | 不理解图片或视频内部的小字；不能自动给出审美判断 |
| 渲染检查覆盖 | `core/render-checked.mjs` 从实际浏览器收集每个渲染帧的检查回执，缺帧拒绝；`render.py` 绑定最终视频 hash | 完整依赖/Chromium 在目标宿主必须可用；不能用普通 CLI 绕过后仍声称通过 |
| 时间与声音 | 原有真实配音、对齐、剪辑指纹、语速/气口/尾静音规则 | 草稿可明确无配音；正式制作不能用静音占位 |
| 画面信号 | `qa.py` 默认硬问题返回非零；`--advisory` 只是诊断，不改变报告里的失败 | 白底、空间覆盖、冻帧等统计部分是审阅提示，不等于视觉缺陷判决 |
| 实际视听 | `visual_review.py extract` → 真正看关键帧、完整播放/试听 → `record` | 初始模板全是未审阅；工具不具备视听能力时不能自动填通过 |
| 交付 | `delivery.py check` 核对当前工程、媒体文件、对应最终视频、机器 QA、视听记录 | 这里只判断视频；封面、文案、音源使用范围另行验收 |

`qa.py` 的硬项目前为高频闪变/亮度跳变、异常持续黑帧、未说明的过长静止段和错误/截断语义锚点。灰度空间分布、小接触表、ASR 都不是文字排版或音画语义一致性的证明。

## 真正观看时回答

开头有什么值得留下的东西？静音时能否理解主视觉？旁白说到某个动作时，画面是否正在展示它？有没有“动了很多但没讲清楚”的地方？界面里的关键字在手机观看尺度是否可辨？实际音量下人声是否清楚，音乐有没有盖字？不同画幅是不是重新构图而不是简单裁切？结论有没有夸大演示能证明的范围？

在 `out/qa.md` 写具体时间码、问题、修改和复看结论。允许有意的全屏实景叠字，但要声明背景层，并保护可读文字与关键证据。技术测试的示例画面不是成片风格目标。

发布后有数据再记留存/完播/收藏、统计窗口与同类基线；不把相关性写成确定的爆款公式。
